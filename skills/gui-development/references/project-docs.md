# 项目资料落盘与维护

适用：组织项目资料、维护文档和管理临时产物。新项目没有既定文档结构时，默认采用下述分类；已有结构时将资料对应到现有目录。

## 默认结构示例

```text
docs/
├── requirement/    需求、产品范围、目标行为与业务约束
├── protocol/       接口或设备协议
├── ui-prototype/   原型代码、截图、链接索引与 UI 补充说明
├── architecture/   工程方案、架构与逻辑图示、模块及服务边界
├── acceptance/     验收标准、任务清单、进度、执行结果与必要证据
└── ...             其他按项目需要维护的资料
```

没有既定结构时，需求、原型、架构与验收资料分别进入对应分类。分类按实际需要创建和扩展，文件名按内容选取；已有明确文档约定时沿用其组织方式。

## 资料落盘与维护

- 本地原型代码、原型截图与 UI 说明归入项目的原型资料；Figma、在线原型等外部资料保留链接和必要补充，不重复复制整套材料。
- 需求资料说明产品应有的目标行为、业务规则、约束及重要假设与范围取舍。基本验收标准、细化清单与执行结果统一放入验收资料，通过引用需求、协议或原型建立依据，不在两处维护同一份验收清单。
- 工程方案、技术选型、关键边界及架构与逻辑图示随架构或方案资料落盘；新建资料用 Markdown，已有适用文档沿用，引用相关原型与协议。局部修改仅更新受影响部分，小修复的方案说明可随现有任务记录维护，不为图示另建一套文档。
- 每个开发/修复任务或独立功能增量实施前，创建或更新当前任务的验收 MD；同一任务的多次代码编辑持续维护同一份记录，小修改可在现有任务文件追加一项。文件名按任务选择，阶段汇报与交付给出当前文件入口，不为每次保存代码新建文档。
- 验收 MD 保存当前有效范围与标准、审核项、实际结果、未覆盖项和下一步。维护任务进度与恢复的方法见 [验证与验收范围](verification.md)；长期需要的关键证据择要保留。
- 需求、协议、UI 或架构发生变化时，同步受影响的资料与图示，注明尚未实现或未验证的部分；只读方案或评审任务仅提出组织建议，不创建目录或修改文件。

## 临时产物

临时产物集中放入项目临时目录。以下示例使用项目根目录的 `temp/`：

```text
temp/
├── acceptance/     测试日志、批量截图、录屏、诊断数据等临时验收产物
└── ...             其他临时文件
```

实际采用的临时目录按 [项目 Git 约定](project-git.md) 加入忽略规则。长期文档需要的证据移入相应文档目录再引用，避免引用会被清理或忽略的临时文件。
