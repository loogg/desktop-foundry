# 纯前端与 Web

适用：交付或本次审查对象直接运行在浏览器中，包括静态前端和调用既有服务的 Web 应用。桌面壳中的 Renderer 按桌面架构参考处理。

## 技术栈与架构示例

简单页面可为 HTML/CSS/JS；组件化项目可为 React/Vue + TypeScript + 既有 HTTP 服务。这些是架构示意，按已有项目采用对应框架。

```text
页面 / UI 状态 → 既有接口契约 → 服务
```

无后端的纯前端任务使用浏览器能力完成其功能，不增加桌面 Bridge 或凭空创建后端。

## 经验与约束

- 以实际路由和接口为依据，沿用数据、错误与鉴权契约。UI 正确展示请求中、失败、取消及成功结果，不把本地状态变化说成服务操作成功。
- 联调使用项目已授权的实际服务。Mock/Fixture 补充空态、错误或难复现状态，并标注覆盖边界；仅交付前端的任务按该范围验收，明确服务联调未覆盖。

## 启动与审查

1. 从项目配置确认页面启动入口、所需服务、访问地址和数据条件；静态页面无需业务服务也应运行真实页面脚本。
2. 按细化界面清单使用内置浏览器执行本次审查流程及所需自动交互，实际查看页面及截图，按索引中的共同方法检查视觉、状态、宽高变化及 favicon/产品标识；接口有影响时同时核对实际请求和响应。
3. 沿用项目测试工具与既有回归套件验证逻辑与边界，自动测试通过不代替第 2 步的交互与视觉判断。页面或服务无法启动先定位环境/接口问题，不以预览页或静态截图代替目标页面运行结果。
