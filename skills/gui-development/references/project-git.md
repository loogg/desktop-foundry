# 项目 Git 约定

适用：开发任务中的版本控制、忽略规则与增量提交。按用户和项目已有约定执行；只读评审仅检查状态。

## 开始与增量推进

- 开始前检查仓库根目录、工作区和暂存区，区分已有工作与本次改动。新建项目尚未纳入 Git 且无相反约定时，在明确的项目根初始化；已属于父仓库的项目不重复初始化。
- 按实际技术栈补齐 `.gitignore`，覆盖依赖、构建输出、缓存和临时目录；保留需要维护的源码、配置与文档。
- 增量验证通过后，按已有自动提交约定或本次提交指令保存 Git 检查点；没有提交约定时保留工作区并交付差异。提交前检查实际 diff 和提交内容，确保只包含本次授权改动及相关文档。已有暂存内容不在本次范围时隔离本次提交，保留其原有状态；无法可靠区分时保留工作区并说明。
- 提交不触发产品升版或打包；桌面交付仍按版本与打包参考的触发条件处理。推送、合并、打标签等按已有明确授权执行，不由本地提交推断。

## 验收资料的保留与忽略

| 资料 | Git 处理 |
|---|---|
| 验收标准、清单、方法、任务进度与恢复信息、结论及未覆盖项 | 作为项目文档保留 |
| 长期文档需要的少量关键截图或其他可共享证据 | 择要保留，确保文档引用有效 |
| 本轮大量截图、日志、录屏、诊断导出及中间产物 | 放入项目临时目录并忽略 |
| 私有输入、真实用户数据、设备敏感信息及凭据 | 按项目数据规则存放，不加入提交 |

采用项目根 `temp/` 时，`.gitignore` 可增加：

```gitignore
/temp/
```

按实际目录调整，不忽略整个 `docs/acceptance/`，也不按图片或数据文件扩展名一概忽略需要维护的资料。已经跟踪的文件不会因新增忽略规则自动移出版本控制，需单独核对和处理跟踪范围，保留本地需要的数据。
