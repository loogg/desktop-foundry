# 设备协议联调

适用：涉及串口、网络或其他外部设备通信，需要选择或建立协议联调环境的 GUI 开发任务。

## 协议依据与环境选择

确认用户提供或项目指定的协议版本、设备角色和扩展资料，核对报文、数据类型、参数、命令与响应、状态、事件及时间约束。关键规则缺失或冲突时，先查证或必要澄清，保留依据与待决项；自行提出的演示契约须标明假设，不能作为厂商协议兼容的证明。

| 联调条件 | 处理方式 |
|---|---|
| 已有适用设备与可用测试环境 | 复用现有环境；按自动回归或故障复现需要补充模拟能力。 |
| 已有候选模拟器 | 核对协议版本与完整功能，补齐差距后复用。 |
| 协议明确，但缺少可控联调环境或需要可重复的设备行为 | 将完整协议模拟器纳入开发任务，按功能分批实现与验证，持续推进至完整覆盖。 |
| 协议关键规则尚未确定 | 先解决缺口，不能靠自造协议或猜测响应宣称兼容与全功能通过。 |

局部修改依据实际影响复用已有环境，不因读取本参考自动新增模拟器开发。仅方案或只读评审按约定分析环境与缺口，不执行实现或联调。

## 模拟器实现

- 以所提供或指定协议版本的**全部功能**为实现与验收范围，包括全部命令或功能码、数据类型、参数规则、正常与异常响应，以及协议规定的状态、事件、时序和通信方式。不能按当前 GUI 已使用的功能裁剪，GUI 本身仍按产品需求实现。
- 模拟器作为通信对端，接受应用正式协议与通信适配器发出的请求，按协议处理并返回响应或事件；不能通过直接调用模拟状态绕过被测编解码和通信链路，也不能另造方便实现的接口替代已有协议。
- 维护可控的设备状态，使读写、任务执行和后续查询相互一致；按协议实现状态转换、命令确认和错误语义，按联调需要提供可重复的初始状态、延迟或故障条件。
- 网络模拟使用协议要求的实际网络连接；串口模拟在环境支持时通过虚拟串口对等方式接入正式串口适配器。只完成内存流、回环或协议逻辑测试时，保留相应通信层未验证状态，不以另一种传输的测试冒充。
- 模拟器源码、配置与测试随目标项目维护，运行说明记录启动、端口或地址、初始状态、重置和关闭方式。模拟协议可观察的状态与结果，实际物理动作和硬件效果仍由真机验证。

## 完整性核对与联调验收

在当前验收 MD 中维护协议功能与实现、验证结果的对应关系，引用协议依据，至少能查到功能或条款、实现入口、预期结果、实际验证结果及未完成项。沿用已有记录，不另建重复的验收清单。

- 使用协议示例报文、独立预期值或可信对端交叉核对；应用与模拟器互通本身不足以证明双方对协议的理解正确。
- 核对全部协议功能及规定的边界与异常语义。存在未实现、未验证或未解决的关键规则时，不宣称完整协议模拟器通过；持续维护未完成项与恢复条件。
- 联调核对实际端口或地址、请求与响应、设备状态及结果。实际 UI、业务链路与回归范围按 [验证与验收范围](verification.md) 执行，Browser/Native 入口按 [架构与审查参考索引](architecture-and-review.md) 选择。
- 分别记录协议逻辑、串口或网络适配链路、协议模拟器与真实硬件的证据。通过实际业务服务连接协议模拟器属于模拟器联调；本机网络或虚拟串口测试不证明物理链路、无线环境或真实设备通过。
