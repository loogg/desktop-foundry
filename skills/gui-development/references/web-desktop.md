# Web 技术桌面应用的共用约束

适用：以 Web Renderer 为主要界面、通过原生通道访问业务服务的桌面应用。具体技术栈与审查例子见参考索引；普通网站不适用。

本次验证范围与复核分工见 [验证与验收范围](verification.md)，以下补充 Browser 与 Native 通道的约束和验证边界。

## Renderer 与 Browser Review Mode

Electron/Tauri 的 Renderer 与原生运行时解耦，通过统一 API 访问后端能力；原生通道与开发 Bridge 的传输细节收敛在适配层，不散布到页面和组件。

新项目已采用此类架构时，默认提供 Browser Review Mode，使同一套 Renderer 通过以下通道访问同一套真实 Backend Service 实现和事件。用户或项目有相反约束时先解决冲突。

- Native 模式通过 Electron IPC / Tauri Command 及相应事件通道访问真实后端。
- Browser 模式通过仅限开发环境的本地 Bridge 访问共用业务服务，不另写一套仅用于预览的业务逻辑。Bridge 的具体传输与服务部署根据项目契约和运行条件选择。

- 明确 Native 与 Browser 通道的契约、业务职责和状态归属，两种通道复用实际业务实现；核对请求、结果、错误与事件语义，按功能检查订阅释放、重连和状态恢复。
- 涉及服务或设备能力时，从 Renderer 追到实际处理器和状态源，确认请求和事件进入真实链路。名称叫 Bridge、显示已连接或接口同名不证明真实性；模拟服务/设备反馈仍属于 Fixture。纯前端功能按真实输入与功能预期验证。
- Mock/Fixture 只补充异常、空态、大数据量等难以稳定复现的界面状态，不替代真实 Bridge。设备协议模拟器可以经真实 Backend Service 验证通信链路，其证据范围为“模拟器联调”，不能直接推断真实硬件通过。
- 每次审查明确所用后端会话与数据目录。独立启动的服务实例须说明状态和能力差异，避免多个实例争用同一设备或文件；共用实现不代表所有实例共享同一份运行状态。

## 开发期安全与测试范围

- Bridge 显式启用、限于开发环境并默认绑定回环地址；在构建或打包阶段排除 Bridge 及开发启动入口，生产运行不得启动或暴露入口，检查实际产物与监听情况。
- 具备开发会话鉴权、来源校验（包含事件通道）、受限 API、参数与权限验证。检查页面代理、监听器及转发链路的实际可达范围；仅回环绑定或 CORS 不构成完整鉴权。
- 浏览器只访问审查所需能力；文件通过受控选择或句柄传递，不提供任意文件、进程或原生能力透传。
- 涉及真实设备、文件写入或配置变更时，核实测试对象、允许动作与隔离环境。不要未经核对就运行可能自动连接设备、加载日常数据或安装更新的审查脚本。

## Bridge 与原生契约验收

- 按需求和实际 API 列出所选验证范围内的业务能力及 Native/Browser 通道，核对相应契约的正常流程与关键失败路径；仅鉴权、方法拒绝或一次成功请求属于基础检查。
- 核对参数、结果、错误与事件语义，以及相应 UI 反馈。保存/读取、报告、订阅、取消、重连与资源释放等仅按项目实际功能展开；验证真实状态、文件或输出，不能只看前端提示或接口状态码。
- 复用有效的模型与业务服务测试，分别核对两种通道的实际适配链路与特有行为。共用实现的测试不能直接证明每个适配通道通过，也无需把同一套模型用例机械重跑到所有通道。记录已覆盖能力和未覆盖项，审核覆盖不以测试数量判断。

## 界面审查与桌面验证

- 有可用 Bridge 就复用。缺少时说明差距及新增适配/服务调整的范围；局部任务可先用现有原生审查手段，不自动扩大为架构重构。
- 启动 Browser Review Mode，在内置浏览器实际操作和观察共享 Renderer；业务流程优先通过真实 Bridge，Mock/Fixture 只补充特殊状态，按参考索引的共同方法检查。
- Bridge 与 Mock 检查通过不代表真实桌面应用通过。用 Computer Use 或适用的桌面自动化操作真实应用并观察画面，验证受影响的原生通道、窗口、对话框、文件、权限、设备与其他系统能力。
- 本次需验证的桌面流程从真实 UI 发起，确认原生适配层与实际 Backend Service 的链路及结果；共享 Renderer 的有效证据可复用，原生差异与集成单独核对。
- 分别记录 Fixture、真实服务、模拟器、原生和硬件的实际证据。
