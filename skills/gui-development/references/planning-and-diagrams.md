# 工程方案与图示

用于分析实现条件、表达工程方案并在实施前自查。ASCII 图示表达系统边界、模块职责及业务逻辑，按任务的不确定性和影响范围决定深度。

## 从项目事实形成方案

- 读取相关入口、调用链、模块约定与已有方案，确认哪些能力可以复用、哪些部分需要修改。技术栈与运行载体的参考选择见 [架构与审查参考索引](architecture-and-review.md)。
- 明确本次输入输出、模块职责、接口契约与状态归属；涉及进程、线程、原生能力或外部服务时，说明实际边界及其影响。
- 异步或持续任务关注任务生命周期、结果确认、并发操作与结束后的状态；适用质量风险和验证条件见 [验证与验收范围](verification.md)。关键依赖、接口能力或运行条件未经核实且影响选型时，先定向查证或做小规模可行性验证。
- 结合已有原型或界面说明，核对操作如何触发业务、数据如何回到界面、哪些状态需要保持一致。原型的完整程度与业务规则、接口及运行条件的完整程度分别判断。

## 按需要选择图示

| 图示 | 适用情况 | 表达重点 |
|---|---|---|
| 架构与模块图 | 系统组成、职责、依赖或运行边界需要说明 | 模块职责与依赖，实际进程、线程、外部系统及服务边界。 |
| 业务流程与数据流图 | 处理步骤、分支、调用或数据流向影响实现 | 输入、处理与输出，命令、结果和事件的传递，数据与状态归属。 |
| 状态或时序图 | 异步、持续任务或操作先后关系影响正确性 | 关键状态、事件与转换、正常路径及适用的失败、取消和恢复。 |

选择能解释当前方案的一种或组合；局部修复的关系已经清楚时，简短说明或调用链即可。已有适用图示直接引用，需要变化时更新相关部分。

UI 在工程图中作为模块，表达事件输入、业务调用与状态更新关系。简单画法示例：

```text
[UI] --操作--> [应用服务] --请求--> [外部适配]
[UI] <--状态-- [应用服务] <--结果-- [外部适配]
```

## 实施前自查

- **需求覆盖**：主要任务是否都有承接，范围取舍是否有依据，是否因自行设定的场景漏掉重要能力。
- **职责与边界**：关键职责、接口、状态归属及运行边界是否清楚，是否符合既有项目与本次约束。
- **任务闭环**：输入、执行、结果和后续操作是否连贯，适用的失败、取消、恢复及资源释放是否有处理路径。
- **可行性与验证**：影响正确性或选型的不确定点是否已解决或明确标注，方案是否支持既定验收条件。

缺口返回需求或方案阶段修正后复核，常规取舍自主完成；无法合理确定且影响正确性的关键问题向用户澄清。方案和图示随实现维护，记录位置与更新方式见 [项目资料落盘与维护](project-docs.md)。
