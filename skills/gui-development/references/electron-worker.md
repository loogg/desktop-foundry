# 示例：Electron + 外部 Worker

适用：界面使用 Electron Web Renderer，某些系统或领域能力由独立进程提供。与桌面共用约束一起使用。

## 技术栈与架构

技术栈示例：React/TypeScript + Electron/Node 调度 + C#/.NET Worker。图示由 Node 管理窗口、文件选择、队列与 Worker 生命周期，Worker 执行领域任务。

```text
共享 Renderer → AppAdapter
                 ├─ preload / IPC ─┐
                 └─ HTTP + SSE ────┴→ Main 服务 → Worker → 系统能力 / 输出物
```

Worker 的命令和事件可通过 stdin/stdout JSONL 等明确协议传递；按项目已有契约实现，不额外重写领域引擎。

## 实现参考

- 图示由 Main 调度 Worker，两种 UI 通道访问同一套服务处理器；也可由独立服务承担调度，按系统能力、现有实现和部署条件取舍。
- 可用受控文件句柄、任务标识及清晰的命令/事件契约连接 UI 与服务。文件权限、任务所有权与生命周期由相应服务负责验证和管理。
- UI、服务与 Worker 的职责根据任务确定；线程与并发策略遵循底层库约束，保留真实进度、取消、错误和结果语义。

## 启动核对与审查

1. 区分真实 Browser Review、原生运行和 Mock 预览三种入口；查明宿主、业务服务与 Worker 的构建及启动依赖，先用健康/环境诊断确认服务是否就绪。
2. 在浏览器操作共享页面，核对真实任务的加载、进度、错误、取消和完成状态，确认事件及结果来自实际服务/Worker。文件选择可能仍打开原生对话框，按实际工具能力处理；Mock 的覆盖范围单独记录。
3. 在真实 Electron 验证受影响的窗口、对话框、文件、IPC 与 Worker 集成，核对服务端参数、权限与任务所有权校验，以及开发 Bridge 的鉴权和生产边界。适配器单测不覆盖真实 Worker 或系统能力。
4. 使用按项目要求隔离的审查数据，功能交付文件时检查实际输出物。文档工具可检查结构及实际渲染页面；其他领域按产物制定验收，不能只验证按钮或进程退出码。
5. 沿用现有 Renderer、Bridge、Worker 和集成测试，核对受影响的构建资源；交付包按 [桌面版本与打包](desktop-packaging.md) 核对本次涉及的 Worker 资源与相关安装行为。
