# 主题探索

用于只有主题方向，或某个模块的主要场景与能力范围尚未形成的部分。

## 从主题形成开发范围

1. **理解目标**：从用户描述、提供材料与已有产品寻找线索，识别使用者、要解决的问题、使用条件和成功结果，说明重要场景假设。
2. **展开能力**：探索主要使用方式、能力分支和典型任务，梳理操作前后的输入输出与任务关联。可从单个与多个对象、一次处理与持续运行、查看与比较或诊断等差异展开，线索按主题取用。
3. **补足知识**：围绕知识缺口定向研究，核实影响范围与实现的领域规则、平台能力和典型用法，优先采用官方文档、标准或可信领域资料。相关产品功能作为候选思路，结合用户任务判断是否采用。
4. **贯通任务**：检查准备、执行、观察结果、后续处理和结束等相关环节，识别必要的失败与恢复路径。适用质量风险与可验证标准按 [验证与验收范围](../verification.md) 处理。
5. **收敛范围**：依据用户目标、任务相关性、典型程度、明确约束和实施条件，决定主要候选能力的纳入、简化、暂缓或排除。当前示例数据、演示场景或单个测试对象，不作为缩窄原始主题的唯一依据；实现范围与可验证范围分别说明。
6. **回看完整性**：对照原始主题与主要候选任务，检查有无重要遗漏或过早收窄，确认本次范围能够支持预期结果。

结论包括用户可完成的任务、预期结果及影响范围的重要取舍。主要取舍用文字或小表说明“候选能力、支持的任务、本次处理与理由”即可；已明确的范围和限制直接沿用。记录方式遵循主流程与本次授权。
