# 定向补全

用于目标和大部分需求已明确，仅有部分功能、流程、规则或状态缺失的情况。

## 围绕缺口分析

1. **定位缺口**：对照明确的目标、已有规则、原型和当前实现，指出缺失或冲突的信息，以及它影响的操作与结果。
2. **补齐任务**：在缺口影响范围内梳理输入、校验或处理、结果反馈与后续动作，考虑适用的失败、取消和恢复。已有决定直接沿用，普通实现细节依据项目约定自主处理。
3. **核对关联**：检查补充内容与相邻任务、接口及共用状态是否一致；领域规则不确定时围绕该缺口查证。需求已经清楚而实现条件仍不确定时，转入 [工程方案与图示](../planning-and-diagrams.md) 分析。
4. **形成依据**：说明补全后的操作、预期结果、约束与重要假设，核对原任务仍然连贯。超出明确范围的新能力作为建议，不自行纳入交付。

如果某个模块连目标或主要场景都尚未明确，只对该部分采用 [主题探索](topic-discovery.md)，其余明确内容继续沿用。结论按主流程记录，验收项统一维护在当前任务的验收资料中。
