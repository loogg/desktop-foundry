# 原生与混合界面

适用：WPF、WinForms、Qt Widgets/QML 及其他原生或混合 UI。

## 技术栈与架构示例

- C# + WPF/WinForms：原生视图通过项目的业务层访问系统与数据。
- Python + PySide/Qt 或 C++ + Qt：Widgets/QML 界面通过项目服务访问设备或数据。
- 原生宿主 + WebView：分别识别原生窗口、嵌入页面和宿主接口。C# 仅用作 Electron Worker 时应读 Worker 参考，不能归入此类原生 UI。

```text
实际 UI 框架 / 原生宿主 → 项目业务层 → 设备 / 系统 / 数据
```

## 经验与约束

复用项目启动、控件定位和自动化能力；在真实应用审查，不为浏览器另做替代产品的 Web 界面。混合项目可用共享页面的真实调试入口检查 Web 部分，原生宿主及集成仍须验证。框架专门规则以项目证据和官方资料为准。

## 启动与审查

1. 确认目标平台、真实程序入口、测试数据与设备安全范围；从项目读取窗口/缩放支持条件，启动实际应用。
2. 按细化界面清单用 Computer Use 或适用的原生 UI 自动化，在真实窗口完成相关点击、输入、菜单、弹窗、滚动和键盘操作，检查焦点与操作反馈；不以直接调用业务接口代替控件交互。
3. 实际查看窗口及截图，按参考索引的共同方法判断视觉、相关状态、布局与产品图标。检查项目支持的窗口尺寸和显示缩放，观察文字可读性、控件裁切、弹窗位置和主要操作可达性；混合界面还须检查宿主与嵌入页面的集成。
4. 核对实际服务、设备或输出结果，发现问题后修正并复验受影响流程。记录实际检查的平台、尺寸、缩放和状态；模拟数据只支持其覆盖范围，工具不能操作或观察真实原生窗口时列为未验证，不推断全平台兼容。
