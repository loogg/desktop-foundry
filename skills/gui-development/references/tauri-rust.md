# 示例：Tauri + Rust 业务服务

适用：Tauri 的 Web UI 通过原生命令与事件访问 Rust 服务。与桌面共用约束一起使用。

## 技术栈与架构

技术栈示例：Tauri + React/TypeScript + Vite + Rust；UI 可组合 Tailwind、Radix、Zustand、TanStack 和 Recharts，Rust 异步服务与开发 HTTP 适配可使用 Tokio/Axum，按项目需要选择。

```text
共享 Renderer → 调用 / 订阅封装
                 ├─ Tauri command / event ─┐
                 └─ HTTP / SSE ────────────┴→ Rust application service / AppState
                                               → 设备 / 系统 / 数据
```

## 实现参考

- 图示将设备通信和业务处理放在 Rust 应用服务，两种通道复用服务与 AppState。可结合现有组件、性能和部署条件调整职责与状态组织。
- UI 中的离线解析、展示计算等功能按需求实现，复用项目协议能力；真实设备结果仍来自实际通信链路。
- HTTP/SSE 是图示的浏览器适配方式，实际传输按命令与事件契约选择；长任务采用适合项目的异步与反馈机制。

## 启动核对与审查

1. 从前端/Tauri 配置确认 Renderer、实际后端、开发 Bridge、代理及模拟器入口；真实链路验收先确认后端就绪，仅启动前端不证明设备操作成功。
2. 在浏览器完成本次流程，核对两种通道的命令、参数、错误及事件语义，以及停止、取消和订阅释放。通信变更用已授权模拟器或测试设备核对，本地状态变化不冒充真实设备结果。
3. 在真实 Tauri 检查受影响的命令/事件、窗口、对话框和系统权限，核对开发 Bridge 的启用、鉴权、Origin 与代理范围。浏览器布局通过不覆盖宿主窗口及原生集成。
4. 沿用前端测试、Rust 测试及已有联调脚本，分别记录 UI、服务、模拟器和硬件的覆盖范围。设备配置与固件写入等操作必须属于已明确的安全测试范围。
