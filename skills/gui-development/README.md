# GUI 开发工作流（gui-development）

按约定需求范围完成 GUI 产品开发或修改：以功能增量推进实现和验证，完成需求覆盖核对、实际界面审查与最终集成验收后交付。

版本 `0.5.0`，作者 `loogg`。[SKILL.md](SKILL.md) 规定公共流程；本页提供调用模板；[参考索引](references/architecture-and-review.md) 提供技术栈、架构示例与对应审查方式。

## 提示词模板

你可以直接这样说。替换方括号，删除不需要的选填行。工作位置默认当前项目，新建独立项目或跨项目时再填写；目标有歧义时先明确位置。项目中已有的信息可给文档入口，有原型时注明页面与状态，配合能力填名称和用途。

### 新项目开发

```text

UI 原型（选填）：[Figma 文件/节点、在线原型、原型代码或截图；本次涉及的页面与状态]
设计与协议（选填）：[设计规范、接口或设备协议]
配合能力（选填）：[本次选用的插件或 Skill，以及用途]
既定选型与约束（选填）：[已确定的 UI 框架、运行平台、依赖许可等]
测试环境（选填）：[可用服务、模拟器、测试设备及允许操作范围]
交付要求（选填）：[指定产物范围或覆盖默认交付；目标平台、架构和版本号如有]

直接完成本次范围；涉及无法自行确认的关键需求或重大选型时再询问我。
有原型时按其页面结构、布局、关键状态和交互意图实现；未覆盖内容依据需求补齐。
按填写的用途配合使用插件或 Skill，界面实现与打磨以给定原型和项目约定为依据。
连续推进所有约定需求，阶段完成时继续剩余工作；按 Skill 完成修正复验、整体核对和核心流程验收后交付约定产物及验证结果。
```

### 可选的调用偏好

配合能力可填写本次选用的设计、实现或测试插件与 Skill，例如 Figma、Taste、Impeccable；写明各自用途，并在发送前选中或附上对应能力。

> 配合能力（选填）：Taste，用于依据给定原型和项目规范完成界面实现与细节打磨。

需要先看方案时，将开发模板中的执行方式替换为：

> 先给出方案、改动范围和基本验收标准，等我确认后再开发。

审查工具、报告形式或协作方式有偏好时，可追加：

> 审查优先使用 [工具]；结果记录在 [位置或形式]；Agent 协作采用 [方式]。

这些是本次调用参数。项目的固定启动命令、支持尺寸、协议路径和安全范围仍以项目事实为准。

## 使用方式

可直接让 Agent 读取本目录的 `SKILL.md`；已安装 Skill 时使用 `$gui-development`。找不到 Skill 时可显式提供文件路径。

本 Skill 用于 GUI 开发流程；纯后端、命令行、UI 原型制作及普通网页操作按各自专业任务处理。

## Troubleshooting

- 找不到匹配参考：确认实际 UI 框架和运行载体，采用项目约束与公共流程；参考示例不限定可用技术栈。
- 浏览器可操作但后端未连接：检查所选适配器和真实调用链，区分 Fixture、真实 Bridge 与原生运行；审查入口能打开不等于业务链路通过。
- 审查工具不可用：采用可用且适合真实应用的工具；缺少实际操作或视觉证据的部分列为未验证。
