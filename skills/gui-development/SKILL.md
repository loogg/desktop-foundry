# GUI 开发工作流

## 1. 分析需求与项目，选择参考

读取需求、设计、协议和相关实现，明确本次目标、成功结果及影响范围，按需求清晰程度选择分析深度。

| 需求情况 | 处理重点 | 读取材料 |
|---|---|---|
| 只有主题方向 | 展开主要场景、能力分支与典型任务，再收敛本次范围。 | [主题探索](references/discovery/topic-discovery.md) |
| 目标明确，功能或流程有缺口 | 围绕既定目标补足缺失环节、规则与状态。 | [定向补全](references/discovery/gap-completion.md) |
| 已有详细需求 | 沿用明确决定，核对冲突、遗漏和执行约束。 | 发现缺口时选用对应参考；工程问题见 [工程方案与图示](references/planning-and-diagrams.md)。 |
| 局部修改或修复 | 定位预期行为、复现条件、相关调用链及直接影响。 | 按涉及内容选择参考。 |

按模块分别判断，可以组合使用不同方法；需求完整程度与工程不确定性分别分析。区分用户明确要求、资料依据与待验证假设；领域规则或依赖行为不确定时定向查证，保留影响方案的来源、适用条件与未决问题。

继续开发或修复任务时，先读取当前验收 MD 与相关需求、方案，核对已完成、待处理及阻塞，再结合当前实现推进。已有项目优先沿用其技术栈、架构和工具链；新项目根据需求作必要选型。

检查 Git 工作区和已有改动，按 [项目 Git 约定](references/project-git.md) 处理初始化、忽略规则与提交，保留本次范围之外的工作。

涉及资料落盘、文档维护或临时产物管理时，按 [项目资料落盘与维护](references/project-docs.md) 组织资料；新项目无既定结构时采用其中的默认分类。

分别识别语言、实际 UI 框架、运行载体与后端边界，按 [架构与审查参考索引](references/architecture-and-review.md) 读取适用内容。结合需求、现有实现和运行条件选择技术栈、传输与模块划分，参考示例可采用或调整；无匹配参考时依项目约束和必要的官方资料处理。参考冲突先对照用户要求与项目事实，无法确定且影响正确性时明确待决问题。

涉及设备通信时，结合协议完整度和可用联调条件，按 [设备协议联调](references/device-integration.md) 选择测试环境，必要时将设备模拟器实现纳入开发范围。

## 2. 形成方案与基本验收标准

开发或修复任务实施前，先将本次范围、需求依据、基本验收标准及已知审核项落盘到当前任务的验收 MD，明确目标结果、关键约束与交付范围。结合 [验证与验收范围](references/verification.md) 识别相关质量风险、选择验证方式，清单与任务规模相称；排除或延期的需求须有用户或项目依据。详细步骤与测试代码可在实现中补充，不依据已完成的实现倒推合格标准。

按 [工程方案与图示](references/planning-and-diagrams.md) 形成与任务规模相称的方案。新项目在正式实现前落盘初始架构、技术栈与关键边界；已有项目复用相关资料，记录实质变化。模块职责、调用链、运行边界或异步逻辑需要说明时，选择必要的 ASCII 图表达架构、业务流程、数据流或状态/时序；已有适用工程图可直接引用，局部修复可用简短说明。

实施前对照需求自查方案，发现缺口时回到需求或方案阶段修正；影响选型的关键不确定点可先做小规模可行性验证。依据后续验证和实现结果调整方案，同步受影响的需求、图示与验收记录，按用户约定连续推进。

## 3. 实现增量并补充验收项

按当前方案实现，使用项目工具链和所需专业能力。在同一验收 MD 补充具体对象、预期结果和执行方式，随推进更新实际结果、必要证据、未覆盖项及下一步，分别说明业务链路、交互和视觉覆盖。测试代码按风险需要补充在目标项目中，记录规模与任务相称。

完整产品或版本交付包含与产品功能、原型或既有品牌一致的应用标识与图标，验证实际显示效果；日常修改按本次范围处理。平台要求见架构参考。

每个增量完成相关验证后按约定保存或提交，再继续推进剩余需求；阶段结果可汇报，不能将局部通过当作完整产品交付。

## 4. 按阶段执行验证与界面审查

按 [验证与验收范围](references/verification.md) 确定本次检查范围、复核分工与复验时机，并读取实际结果。

验收时读取当前验收 MD，逐项执行适用检查；需要界面审查时，按架构参考在真实应用操作并观察，分别记录业务、交互和视觉结果。桌面任务另按 [桌面版本与打包](references/desktop-packaging.md) 判断升版与打包时机，生成并验证相应产物。

## 5. 定位、修正、复验与交付

区分需求、方案、实现、测试与环境问题，返回相应阶段处理。修正后复验原问题及受影响的关联流程，不机械重跑全部检查；测试有误时依据需求修正，不删除有效断言或降低标准来换取通过。

开发或修复任务交付前核对本次需求与验收覆盖，更新验收 MD 的结论与未覆盖项，按实际结果说明交付状态；无法解除的阻塞说明未完成项与恢复条件，未执行的检查不能计为通过。方案或评审任务按其约定产物结束。
