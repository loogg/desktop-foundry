# 设计画布原型

用户要求和已有项目约定优先。下文以 Figma 术语描述，其他平台按设计意图采用对应能力。

## 1. 按内容职责组织文件

- **Page 划分**：先看需求与已有文件，按内容划分 Page，例如“产品界面”“设计系统”“数据模型”“理论与计算依据”。内容少时合并，独立且复杂时拆分；名称默认中文，沿用已有适用结构，不固定建齐目录或创建空页。公式编辑器、协议配置等真实产品功能仍属于产品界面。
- **界面与状态**：同一功能的相关视图与关键状态优先放在同一 Section，以业务含义命名。整页变化用 Frame，控件变化优先用组件状态，弹窗等临时内容按需用浮层表达；不为每个局部变化复制整页。

## 2. 呈现产品效果与交互意图

- **产品画面**：只放产品本身会呈现的界面元素，用具体、合理且相互对应的业务内容展示效果。设计讨论、开发待办和为演示额外添加的“样例已载入”“推进事件”等内容不进入产品画面；产品本身的帮助、导入样例等功能正常设计。
- **复杂组件示意**：曲线、仪表盘等可用接近预期效果的组件占位，表达布局、数据含义和交互意图。用 Annotation 标明原型参考范围及正式开发需专用实现的部分；通信、计算可用示意数据表达。

## 3. 在需要的位置补充说明

- **Annotation 适用于任何 Page**：产品界面、设计系统、数据模型、理论依据中，有难从设计本身理解的规则就按需标注。用原生 Annotation 就近关联控件、区域、界面 Frame 或说明对象；标注不作为产品 UI 元素。平台不支持时放在对应画板外，并明确关联对象。
- **共用内容集中放置**：设计系统收纳本项目实际采用的样式、组件、必要状态和共用布局规则；自适应可用规则与局部示意表达，不为说明适配复制整套产品界面。组件共性写入 Description，具体实例只补差异；已有资源与说明有效时直接引用。
- **说明只补缺口**：补充特殊行为、样例范围和未确认假设，不重复画面已表达的信息。跨 Page 的业务依据，在相关对象的标注中注明位置或链接。
