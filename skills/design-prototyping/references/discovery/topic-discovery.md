# 主题探索

用于只有主题方向，或某个模块的主要场景与能力范围尚未形成的部分。

## 展开探索与收敛范围

1. **理解任务**：从提供的材料与已有产品中寻找线索，识别可能的使用者、希望解决的问题与成功结果，提出待验证的场景假设。
2. **展开能力**：识别主题的主要使用方式、能力分支与典型任务，梳理操作前后的步骤、输入输出与任务关联。可从单个与多个对象、一次操作与持续观察、查看与比较或诊断等差异展开，具体线索按主题取用。
3. **补足知识**：结合已有知识与定向搜索，发现尚未考虑的典型场景和能力，并核实影响结构、内容与交互的领域规则。根据问题优先查看官方文档、标准、可信领域资料或相关产品说明。
4. **选择范围**：根据用户目标、任务相关性、典型程度、评审价值与明确约束，对主要候选能力作出纳入、简化、暂缓或排除的取舍。自行设定的示例设备、默认数据或演示场景，不作为排除其他主要场景的唯一依据。
5. **检查完整性**：回看原始主题与主要候选任务，检查是否遗漏重要场景或能力、是否因假设而过早收窄，以及取舍是否支持用户目标；据此形成需要表达的用户任务、预期结果、关键状态与交互意图。

主要取舍用文字或小表说明“候选能力、支持的用户任务、本次处理与理由”，保留影响范围的决定即可。“不是核心功能”本身不足以解释为何排除与主题直接相关的主要能力。

搜索发现的常见功能作为候选思路，结合用户任务决定是否纳入。

方法参考：[IBM Design Research：Craft insights](https://www.ibm.com/design/research/research-in-practice/craft-insights/) 与 [GOV.UK：理解用户及其需求](https://www.gov.uk/service-manual/user-research/start-by-learning-user-needs)。两者支持围绕用户目标、证据与假设开展探索，具体步骤按本次原型任务组织。
