# 定向补全

用于目标和大部分需求已明确，仅有部分功能、流程、规则或状态缺失的情况。

## 围绕缺口分析

1. **定位缺口**：对照已明确的目标、功能、约束和现有设计，指出缺失或冲突的信息，以及它影响的操作或结果。
2. **补齐环节**：在缺口影响范围内梳理输入、校验或处理、结果反馈、后续动作与必要状态。已有适用规则时复用，普通表达细节自主设计。
3. **核对关联**：检查补充内容与既有规则、相邻任务和共用状态是否一致。需要领域知识时，围绕该缺口定向查证，分析其对相关界面的影响。
4. **形成检查依据**：说明补全后的操作、预期结果、反馈与恢复路径，核对原有任务仍然连贯、用户已确定的范围得到保留。

如果发现某个模块连目标或使用场景都尚未明确，回到主文件，针对该模块重新选择分析方法。
