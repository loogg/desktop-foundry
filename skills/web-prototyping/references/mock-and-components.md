# 原型制作约定与示例

以下约定用于制作、修改与检查原型源码。具体注释文案和控件示例按评审目标与当前环境调整，不作为默认业务功能；源码结构按下方约定适配。

## mock 数据与模拟行为

数据、接口、事件、延迟与进度等模拟内容明确命名或注释。mock 数据优先在源码前部集中定义或按业务分组，相关视图保持数据、单位与含义一致；示意结果不作为真实通信、实测或正式业务计算的依据。

按评审目标选择需要的模拟场景，说明关键状态的触发与复现方式。已有数据或资源适用时沿用，区分真实资料与模拟内容。

## 代码组织例子

| 项目情况 | 一种组织方式 |
|---|---|
| 单页原型，只有少量字段与状态 | 在一个主文件中组织顶部说明、mock 数据、显示状态和界面；没有用到的分区无需预建。 |
| 多个视图共享数据和状态 | 共用 mock 与显示规则，按功能分组视图和组件；局部状态切换沿用同一份数据，不复制整套页面。 |
| 已有完整原型，仅改一个功能 | 在现有结构中修改相关视图、状态与说明，沿用技术栈和资源，不为套用模板重排源码。 |

## 代码说明约定

- **顶部说明**：入口或主原型文件开头说明原型用途、覆盖范围、mock 范围、控件占位与正式实现边界，并随内容变化更新。
- **局部注释**：在数据、模拟接口与控件附近补充示意性质、特殊行为、状态复现方式和未确认假设；共用规则引用设计规范，具体实例只补差异，相关业务依据注明位置或链接。说明留在代码中，不作为产品 UI 元素，不重复画面已表达的信息。
- **源码结构**：新建原型以 [TSX 结构模板](../templates/App_Prototype.tsx) 的职责划分和注释结构为起点，按当前技术栈、语法和原型规模组织 mock、状态、共用组件、模拟接口与主界面，省略未使用的分区。已有原型沿用现有结构，落实本次涉及的约定，不为套用模板重排或重建。
- **说明位置**：设计规范、数据模型和理论依据等说明按需放在文档或注释中，不固定建齐目录或加入产品导航；属于实际产品功能的内容仍按产品界面设计。

## 注释文案例子

| 位置与对象 | 文案例子 |
|---|---|
| 文件顶部：配置界面原型 | 本原型用于表达配置页面的布局和保存反馈。列表与保存响应均为 mock，不连接真实设备或后端；正式通信与业务校验按开发需求实现。 |
| mock 数据定义处 | 此集合为人工示意数据，用于展示列表、详情与选中状态；各视图引用同一记录，数值不代表设备实测。 |
| 模拟接口或事件附近 | 此响应只演示加载与成功反馈；失败场景通过本地 mock 条件触发，没有请求真实服务。 |
| 未确认规则附近 | 此处按当前假设表达禁用状态，适用条件待确认；原型不据此确定正式业务规则。 |

HTML 采用 HTML 注释，JS/TS 采用行或块注释，JSX/TSX 元素内部采用 JSX 注释。注释随实际内容维护。

## 复杂控件示意与注释

控件的实现程度取决于本次评审目标。曲线、仪表盘、Toast 等需要表达布局、颜色、大小、数据含义和所需状态时，可用普通元素、CSS、简单 SVG 或已有基础组件占位。需要验证特定交互时，选择能表达该行为的实现；已有组件适用时直接复用，不必另做占位。

采用占位实现时，在注释中说明展示范围及“正式开发使用专用组件实现”。通信与计算的模拟范围按 mock 约定说明，实现工作以本次原型的评审需要为准。

| 控件 | 画面表达 | 对应注释的文案例子 |
|---|---|---|
| 曲线 | 展示绘图区大小、坐标、图例、曲线颜色，以及需要的空、加载或选中状态。 | 此处为曲线效果占位，用于表达布局、颜色与状态；采样数据为 mock，正式开发使用专用组件实现。 |
| Toast 提示 | 用普通容器展示位置、大小、颜色、图标与文案，以及需要的出现、消失或不同反馈状态。 | 此处用普通组件演示提示效果与显示状态；正式开发使用专用组件实现。 |
| 仪表或进度显示 | 展示读数／进度与尺寸、阈值颜色及相关状态的视觉关系。 | 此处用于表达读数／进度与颜色状态；数据和进度为模拟，正式开发使用专用组件实现。 |
