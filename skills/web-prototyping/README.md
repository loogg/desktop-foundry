# Web 交互原型（web-prototyping）

按约定需求范围制作、完善或验收用 Web 技术表达产品界面与交互的可运行原型，供设计评审使用。

版本 `0.1.0`，作者 `loogg`。[SKILL.md](SKILL.md) 提供设计规范、原型表达与效果检查的指导；本页提供调用模板；[制作约定与示例](references/mock-and-components.md) 提供 mock、控件占位与代码说明约定。

## 提示词模板

选中 Skill，按需附上当前平台的工具、设计资源或专业设计能力，替换模板中的方括号；选填行可以删除。已有项目与设计约定优先，不要求固定插件组合。

你可以直接这样说，按任务选用下面的完整模板。

### 从需求制作

```text
使用 $web-prototyping，配合 [当前项目工具或生成平台]，根据以下需求制作用于界面与交互评审的可运行 Web UI 原型。

需求：[需求描述或文档]
目标位置：[源码目录、原型文件或平台项目入口]
设计规范（选填）：[直接附上 design.md 或其他规范，或提供文件路径／内容]
已有设计或参考（选填）：[设计、原型、截图或风格说明]
补充约束（选填）：[目标显示尺寸、已有技术栈、需要的状态与交互]

在一次任务中连续完成以下流程：
1. 制作：按 Skill 分析需求、确定并审核设计规范，完成约定范围的界面与交互原型，完成后立即进入第 2 步。
2. 审查：以资深 UI 设计师的角色，按需求与 Skill 审查本次范围的内容、视觉与交互。查看当前可运行成果的画面或截图，实际操作关键任务、流程与状态；通过则进入第 4 步，有问题则进入第 3 步。
3. 修正：直接修复问题，同步更新受影响的原型与设计规范，复核相关界面、状态与共用组件，然后返回第 2 步，基于最新成果重新审查。
4. 交付：只有本次约定范围内的验收项全部通过后，才最终答复，提供可继续编辑的源码或项目入口、运行或预览入口、验收结论，以及设计规范和原型说明的位置或内容；需要启动时附实际命令。

过程中可以汇报进展，自行推进，不逐轮等待我确认，不在制作阶段结束时最终交付。若有无法自主解决的阻塞，说明阻塞项和已完成范围，不宣称验收通过。
```

### 完善已有原型

```text
使用 $web-prototyping，配合 [当前项目工具或生成平台]，完善以下可运行的 Web UI 原型。

现有原型：[源码文件、项目目录或平台项目入口]
本次改动：[需求或问题]
设计规范（选填）：[直接附上 design.md 或其他规范，或提供文件路径／内容]
补充约束（选填）：[需要保留的内容、目标尺寸、设计或行为约定]

1. 修改：读取现有原型与本次需求，按 Skill 完善本次涉及的设计规范、界面与交互，沿用适用资源，保留范围之外的内容。
2. 局部检查：打开当前成果，仅检查本次改动和直接影响的内容、布局、状态及相关交互，修复问题并复核，不主动启动整体验收或扩大修改范围。
3. 交付：提供更新后的源码或项目入口、运行或预览入口及相关设计说明，简要说明改动与检查范围；需要启动时附实际命令。若我另有闭环验收要求，先完成指定范围的验收再交付。无法检查的项目如实说明，不将局部检查称为整体验收通过。
```

若本次修改也需要闭环审查，在模板末尾追加：“本次改动及其影响范围也要执行内容、视觉与实际交互审查；有问题直接修正后重新审查，直到该范围内验收通过再交付。无法自主解决的阻塞如实说明，不宣称通过。”

### 多轮修改后的整体验收

```text
使用 $web-prototyping，配合 [当前项目工具或生成平台]，以资深 UI 设计师的角色，对以下 Web UI 原型进行整体内容、视觉与交互验收，并修正发现的问题。

现有原型：[源码文件、项目目录或平台项目入口]
验收依据：[当前需求、已确定的设计方向或相关文档]
设计规范（选填）：[直接附上 design.md 或其他规范，或提供文件路径／内容]
验收范围（选填）：[需要验收的页面与流程；留空按当前原型整体检查]

在一次任务中连续完成以下流程：
1. 明确依据：读取现有原型与验收依据，按 Skill 核对设计规范，沿用既定需求和设计方向，确定本次验收范围。
2. 整体审查：按需求与 Skill 检查整个验收范围，不只看最近修改的部分。查看当前可运行成果的画面或截图，实际操作关键任务、流程与状态；通过则进入第 4 步，有问题则进入第 3 步。
3. 修正：沿用既定需求与设计方向，返回相关设计或生成环节定点修复问题，同步更新变化涉及的设计规范，复核受影响的页面、状态与共用组件，然后返回第 2 步，基于最新成果重新审查。
4. 交付：只有约定范围内的验收项全部通过后，才最终答复，提供可继续编辑的源码或项目入口、运行或预览入口、验收结论与主要修正，说明实际检查范围及设计规范和原型说明的位置或内容。

过程中可以汇报进展，自行推进，不逐轮等待我确认。若有无法自主解决的阻塞，说明阻塞项和已完成范围，不宣称验收通过。
```

## 本地安装

在仓库根目录按需安装本地 Skill：

```bash
npx skills add . --skill web-prototyping
```

## Troubleshooting

- **平台没有读取 Skill**：附上主文件约定与所需结构模板，使用对应任务提示词，确认平台实际收到内容。
- **某个 mock 状态无法复现**：检查模拟条件与注释是否一致；重要状态使用明确、可重复的触发方式，避免仅依赖随机结果才能看到。
- **普通占位看不出效果**：补足颜色、大小、布局与本次需要的状态表达，复核当前画面，按需求保持原型实现轻量。
- **无法操作预览或取得源码**：说明当前可执行范围与缺口。未检查的交互与代码说明如实标记，不能仅凭生成结果宣称验收通过。
